## 1. 策略定义

| 条件 | 公式 | 说明 |
|---|---|---|
| ① 横盘 | `(High.rolling(N).max − Low.rolling(N).min) / Low.min < X%`，取**昨日**值 | 用昨日值，避免当天大阳线把箱体自己撑大 |
| ② MACD 金叉 | `MACD_t > Signal_t` 且 `MACD_{t-1} ≤ Signal_{t-1}` | ゴールデンクロス |
| ③ 0 轴附近 | `|MACD| / Close × 100 < zero_band%` | 用价格归一化，跨股票可比 |
| ④ 放量 | `Volume > MA(Volume, 20) × 1.5` | 出来高確認 |
| ⑤ 真突破（可选） | `Close > 过去 N 日最高（不含当日）` | **原版没有这一条** —— 见下方说明 |
| 入场 | 以上条件在 T 日收盘成立 → **T+1 开盘**买入 | 无前视偏差 |

> ⚠️ 原版策略叫"横盘突破"，但 ①~④ 里没有任何一条要求价格**突破箱体上沿**，
> 实际抓的是"突破前的蓄势"。想做字面意义的突破，把 `require_breakout` 打开，
> 然后**重跑 walk-forward** 对比两者的拼接 OOS 曲线，再决定用哪个。

### 可调参数（`qbreak/config.py → StrategyParams`）

| 参数 | 默认 | 作用 | 调大 → |
|---|---|---|---|
| `range_n` | 60 | 横盘回看天数 | 要求横盘更久，信号更少 |
| `range_x_pct` | 15 | 横盘允许振幅 % | 放宽箱体定义，信号更多 |
| `macd_fast/slow/signal` | 12/26/9 | MACD 三周期 | 慢线越大越迟钝、越稳 |
| `macd_zero_band_pct` | 1.0 | 「0 轴附近」容忍带 % | 接受离 0 轴更远的金叉 |
| `vol_mult` | 1.5 | 放量倍数 | 要求更强放量 |
| `require_breakout` | False | 真突破确认 | 打开后信号更少但更"像突破" |
| `trend_ma_n` | 0 | 长期趋势过滤（如 200） | 只在均线上方做多 |
| `min_turnover` | 0 | 最低 20 日平均売買代金 | 建议日本株设 1e8，否则滑点假设不成立 |
| `stop_loss_pct` | 7 | 固定止损 % | 容忍更大回撤 |
| `atr_stop_mult` | 0 | ATR 止损倍数（>0 时覆盖上一项） | 止损随个股波动自适应 |
| `take_profit_pct` | 25 | 固定止盈 %（0=关闭） | |
| `trailing_stop_pct` | 12 | 跟踪止损 %（0=关闭） | 让利润跑更远，回吐也更多 |
| `trailing_arm_pct` | 0 | 浮盈超过该 % 才启动跟踪 | 避免刚建仓就被震出去 |
| `max_hold_days` | 60 | 最长持有交易日（0=不限） | |
| `time_stop_days` | 0 | 时间止损：持有 N 日仍无浮盈则离场 | 释放"死钱" |
| `exit_on_macd_dead_cross` | True | 死叉平仓 | 关掉后靠跟踪止损锁利，更适合抓大波段 |
| `max_distribution_days` | 0 | 信号日前 20 日内「收跌且放量」的出货日数 ≥ 该值则不进场（0=关） | 只剔除最明显的派发；日本株覆盖文件设 6 |
| `max_upper_shadow_ratio` | 0 | 信号日上影线 / 实体 > 该值（冲高回落）则不进场（0=关） | 日本株覆盖文件设 3 |
| `max_rsi` / `max_ext_ma20_pct` | 0 / 0 | RSI 超买 / 离 20 日线过远则不进场（0=关） | 横盘票几乎不会触发，回测无增量，保持关 |
| `min_rs_pct` | −999 | 60 日涨幅须 ≥ 指数 + 该值（≤−900=关；RS 值仍在候补队列展示） | 信号层检验：被 RS 剔除的信号反而更好 → 关 |
| `earnings_blackout_days` | 0 | 决算前 N 个交易日不进场 | 模拟盘设 2 |
| `exit_on_climax` | False | 浮盈 >5% 时出现放量陰線（量 >2.5×均量）次日离场 | 模拟盘打开；回测中性 |

**按市场覆盖**：`var/best_params.json` 是两市场共用的基础参数；`var/best_params_JP.json` / `var/best_params_US.json`
存在时，其中字段**覆盖**到该市场（可以只写差异）。`backtest / optimize / paper / signal / daemon / sim-day` 都按市场自动叠加，
日报「市场状态」栏会标出用了哪个覆盖文件。

## 2. 成交假设（**看懂这一节再看任何收益数字**）

| 项目 | 设定 | 为什么 |
|---|---|---|
| 入场 | T+1 开盘价 ×(1+滑点) | 信号在收盘后才知道，最早只能次日开盘买 |
| 股数 | **信号日收盘就定**：收盘权益 × 仓位% × 宏观倍数，按 收盘×(1+滑点) 换算、单元取整 | 实盘前一晚就要下单，不可能知道次日开盘价（旧版按开盘价定股数，JP 100 股单元边界上会差一倍，见「算法验证」） |
| 资金 / 名额 | 预计可用 = 现金 + 明早卖出的预计净额 − 已计划买入；名额 = 上限 −（持仓 − 明早卖出）− 已计划 | 同日多个信号时逐笔扣减；开盘现金不够按单元减，持仓满（卖单没成交）则放弃 |
| 跳空过滤 | 开盘价 > 信号日收盘 ×(1+3%) 则放弃 | ストップ高 追不进去；实盘用 **寄付指値 = 收盘×1.03**（按呼値取整）实现同一规则 |
| 止损成交 | **`next_open`（默认）**：收盘价触发 → 次日开盘成交 | 一个每天只跑一次的程序**只能**做到这个 |
| | `intraday`：盘中触及即成交 | 只有真的挂了**逆指値（stop order）**才成立 |
| 手续费 | 按券商：立花 個別コース（日本，默认）/ 楽天 0 円（日本）、0.495% 上限 22 美元（美股） | `sim.json` 市场段 `broker`；费率表在 `qbreak/fees.py` |
| 滑点 | 单边 0.1%（JP） | 流动性差的票要调大 |
| 仓位 | 用**信号日（前一日）收盘权益**计算 | 用当日数据就是前视偏差 |
| 単元株 | JP 100 股 / US 1 股 | ETF、REIT 等例外在 `tick.py:LOT_OVERRIDE` 里改 |

回测引擎（`engine.py`）与实盘流水线（`trader.run_once` + `PaperBroker`）执行**同一套**规则，开盘成交顺序都是
「个股卖 → 核心指数卖 → 个股买 → 核心指数买」；`scripts/verify_all.py` 的 V4 用真实数据逐日回放对照（见「算法验证」）。

两种止损模式各跑一次，差额就是"没挂逆指値"的成本：

```bash
python run.py backtest JP                          # next_open（保守、真实）
python run.py backtest JP --stop-mode intraday     # intraday（乐观，需配合 --protective-stop 实盘）
```

### 算法验证（`python scripts/verify_all.py`，结果写入 `var/out/verification.md`）

| 检查 | 方法 | 结果（2026-09-24） |
|---|---|---|
| V1 指标公式 | 逐日循环独立重写 MACD / Wilder RSI / ATR / 箱体 / 量比 / 出货日 / 上影 / climax / entry，全池 × 5 年对照 | 布尔列 0 处不一致；RSI / ATR 相对误差 ≤ 1e-7（种子差，250 根后收敛），其余 0 |
| V2 无前视 | 截断到任一天重算，必须等于全量计算在该天的值 | 指标、宏观特征、利率 beta、4 类牛熊检测器 + HMM、量化状态层：0 处不一致 |
| V3 回测引擎 | 与独立参考回测器 `tests/reference_engine.py` 逐笔对照（含 / 不含宏观倍数） | JP 104/104、US 60/60 笔；权益差 ≤ 2e-10 |
| V4 实盘流水线 | `run_once` + `PaperBroker` 按真实数据逐日回放 250 个交易日，与引擎逐笔对照 | JP 12/12、US 13/13 笔，股数与成交价逐笔一致，权益差 0（修复前 JP 有 2 笔股数不同，见下） |
| V5 公司行为 | 真实事件：NVDA 1:10 拆股、8058.T 1:3 拆股、7203.T 45 円配当 | 股数、止损、税后入账、市值连续性全部正确 |
| 合成差分 | `tests/test_plan_alignment.py`：含核心指数仓位、熊市清空、同日多信号、排队卖出腾名额 | 实盘 = 引擎（JP / US） |

验证中发现并已修复：
1. **股数口径**：回测按次日开盘价定股数，实盘按前一晚收盘价 → 日本 100 股单元边界上差一倍（4503.T 实盘 200 股 / 回测 100 股，6753.T 400 / 300）。统一为「信号日收盘定股数」。
2. **同日多笔买入**：实盘没有预扣前一笔的资金、名额没算排队中的单 → 可能超出持仓上限或开盘被拒。统一为「预计可用资金 / 名额」规则（见上表）。
3. **宏观倍数与现金上限的先后**：回测 min(预算, 现金)×倍数，实盘 min(预算×倍数, 现金) → 统一为后者。
4. **成交日期**：模拟券商用运行时刻记日期（美股晚一天）→ 改为成交 K 线日期。
5. **操作清单的买入指値** 是 收盘+0.5%，比回测的跳空上限（+3%）严 → 照清单下单会错过回测里成交的单。改为 收盘×1.03（按呼値取整）；立花 / RSS 自动下单也改为寄付指値。
6. **行情数据**：1329.T 2014-01 未复权的 1:10 拆股、1306.T 2015 拆股与 2026-03 的一日错价等 → `data.repair_jp_artifacts`（値幅制限下不可能的 ×<0.6 / ×>1.7 跳变：先识别拆股，再剔除一日错价，都不是则截断历史）。
7. **模拟盘风控**与回测不一致（连亏 6 笔熔断，而历史最长连亏 7～8 笔）→ 模拟盘只保留回撤 HALT。
8. **呼値**：TOPIX500 适用细表；2027-03-01 起的 STR 分档已按日期实现。
官方口径核对：祝日（内閣府 CSV）、NYSE 休市日 2026/2027、値幅制限・呼値（JPX）、税率 20.315%、乐天手续费（ゼロコース、美股 0.495% 上限 $22、免手续费 ETF 名单）、立花ｅ支店手数料（個別 / 定額，2026-09-25）、美股分红预扣 10%（日米租税条約）。

## 3. 四个阶段

### 第1阶段　回测

```bash
python run.py backtest JP --years 5
```
输出：交易次数/胜率/盈亏比/每笔期望/CAGR/最大回撤/夏普/索提诺/最大连亏/资金暴露/**分年度收益**，
外加等权买入持有基准对照。产物在 `var/out/`。

**怎么看**：先看分年度表——如果 5 年收益靠某一年撑起来，这个策略你拿不住；
再看"被过滤的信号"，`gap` 很多说明策略在追涨停，`full` 很多说明持仓上限卡住了。

### 第2阶段　参数优化（Walk-Forward）

```bash
python run.py optimize JP --train-years 2 --test-months 6 --save
```
输出四样东西，**只看后两样**：
1. 各窗口 IS 最优参数 → OOS 实测
2. 稳健参数区间（众数 + stability%）
3. **参数敏感度**：某个参数换一档分数就断崖 → 策略对它过敏，实盘会很难受
4. **在所有窗口都进前 20% 的参数组合** ← `--save` 会把它写进 `var/best_params.json`，第3/4阶段自动读取

最后一行「拼接 OOS 曲线」才是接近实盘的期望值。**IS 分数再漂亮也不算数。**
如果第 4 项为空，程序会**拒绝写入** `best_params.json` —— 这时应该改规则（例如打开
`require_breakout` / `trend_ma_n`）而不是继续调参。

### 第3阶段　模拟盘（至少 3 个月）

```bash
python run.py paper JP                # 每交易日 16:10 JST 之后运行一次
python run.py status                  # 看持仓/权益/风控状态
```
- 模拟盘的订单会**排队到次日开盘成交**，与回测引擎完全一致 —— 这样"第3阶段验证第1阶段"才有意义
- 状态在 `var/state/`，日志在 `var/logs/`，每日流水在 `var/out/journal.csv`
- 跑满 3 个月后，把 `journal.csv` 的胜率/平均单笔和回测对比；**对不上先查数据和成交假设，不要先改策略**

### 数据源双保险（云端网络策略之外的永久解法）

云端 worker 每天先做连通性检查；Yahoo 被拦截时**自动改用 `var/csv/`**。谁来填 `var/csv/`？
任何一台有外网的机器（比如你的 Mac）：

```bash
bash scripts/install_launchd_fetch.sh     # 每天 06:30 JST：fetch-data → git push
bash scripts/fetch_and_push.sh            # 或手工跑一次
```

两条路只要通一条，模拟盘就不会断。日报横幅会显示当天用的是 `yfinance` 还是 `csv`，以及被拦截的域名。

### 牛熊分界与熊市算法（`qbreak/bullbear.py`，2026-09-24）

**一、牛熊的精确定义（事后标注，精确到日）**：收盘从最近高点回落 ≥20% → 高点次日起为熊市；从最近低点反弹 ≥20% → 低点次日起为牛市（Lunde–Timmermann 阈值法）。
S&P500 自 1950 年 13 次熊市，日経225 自 1965 年 26 次；清单：`python run.py bullbear --history`。这个定义只有事后才知道（宣布时已跌 20%）。

**二、实时分界算法（每天收盘后可用）**：收盘**连续 5 个交易日低于 250 日均线 × 0.97 → 熊市**；**连续 5 个交易日高于 250 日均线 × 1.03 → 牛市**。
从 4 类 149 个候选（均线带 / 回撤反弹阈值 / 混合 / 2 状态隐马尔可夫）中选出。选择规则事先写定：只用 2005 年以前数据（S&P 1951–2005、日経 1966–2005），
约束「每年切换 ≤1 次」且「择时组合 Calmar ≥ 买入持有」，目标「牛/熊召回的平均最大」。2006–2026 样本外：

| 样本外 2006-01～2026-09 | S&P500 | 日経225 |
|---|---|---|
| 平衡准确率（训练期） | 0.772（0.721） | 0.707（0.766） |
| 熊市识别延迟，自高点起（中位） | 39.5 交易日 | 30 交易日 |
| 牛市识别延迟，自低点起（中位） | 98 交易日 | 62 交易日 |
| 事后熊市段数 / 漏报 / 误报 | 4 / 0 / 5 | 11 / 2 / 3 |
| 每年切换次数 | 0.77 | 1.06 |
| 指数择时：熊市持现金 年化 / 最大回撤 | 7.73% / −26.7% | 5.60% / −36.3% |
| 指数买入持有 年化 / 最大回撤 | 9.18% / −56.8% | 7.00% / −61.4% |

参照：单纯 200 日线每年切换 5～6 次（被规则排除）；实时 20% 规则延迟 60～70 交易日；50/200 均线交叉日本每年切换 1.15 次。
每天的「翻转价位」（明天收盘低于多少、连续几天会转熊）写在日报「市场状态」卡片与 `run.py bullbear` 输出里。

**三、熊市算法（现物账户只能做多：现金 / 1 倍反向 ETF / 超跌反弹）**——指数层面，训练 ≤2005、样本外 2006～，只统计熊市状态内：

| 熊市算法 | S&P 训练 / 样本外 年化 | 日経 训练 / 样本外 年化 | 结论 |
|---|---|---|---|
| 现金 | 0 / 0 | 0 / 0 | **采用** |
| 1 倍反向全程持有（1571 / SH） | −1.10% / −3.09%（回撤 −70%） | −1.14% / −4.65%（回撤 −80%） | 不用 |
| 1 倍反向 + 10% 止损 | +0.16% / −1.21% | +0.47% / −2.35% | 规则按字面选中，但训练优势≈0、样本外两市场都亏 → 不部署 |

### 盘中守护进程在做什么

```
休市 → 睡到下一个开市时刻          08:50 → 开市前对账
09:00–11:30 / 12:30–15:30 → 每 60 秒：取现在值 → 更新峰值 → 检查止损/止盈 → 维护逆指値
15:25 → 收盘竞价前最后一次风控      15:40 → 日线信号 → 次日寄付单 → 日终对账
```

**盘中不重算信号**：当前策略的信号定义在收盘价上，回测也是这么验证的。盘中重算会产生
大量盘中出现、收盘消失的假信号，而且无法用现有回测验证。真正的日内策略是另一个项目。

## 6. 已知局限（原版列出的仍然成立，加上新的）

1. **横盘突破策略的胜率通常 30~45%**，靠盈亏比赢钱。默认 `exit_on_macd_dead_cross=True` 会过早砍掉大趋势；想抓大波段应设为 False 并依赖跟踪止损。
2. **幸存者偏差**：回测股票池是 2026-09 时点的成分股，5 年回测因此偏乐观（被剔除的弱势股不在池里）。今后的指数入替通过 `var/index_changes.json` 按时点生效，但历史部分无法补齐。
3. **20 只 × 5 年信号很少**（每年个位数），统计意义弱。扩到 100+ 只再谈参数稳健性。
4. **yfinance 是非官方接口**，可能限流/改版。行情为复权价：回测含分红（按再投资、税前计，约高估 0.1～0.2%/年）；模拟盘 / 实盘的除息与拆股由 `corpactions.py` 补记（见上表）。
5. **呼値表 2027-03-01 起按个股流动性（STR）分 A/B/C 三档**：`qbreak/tick.py` 已按日期切换（未登记的股票按 C 表、单元 1 的 ETF 按 O 表）；
   JPX 公布各股所属档位后填进 `tick.STR_CLASS`。
6. **値幅制限**只能从日线推断「一整天张贴」，盘中短暂触及涨跌停不影响寄付成交的情形按正常处理；制限値幅的拡大（連続張り付き時）未建模。
7. 本框架只做**現物・買い（做多）**，不含信用取引、空売り、分批建仓/加仓。
8. **差金決済**：現物では同一銘柄・同一営業日・同一資金で「買→売」1 往復まで。
   2 往復目は券商侧で拒否される（`DaemonConfig.max_round_trips_per_day` 会先拦一道）。
   不同股票不受此限。
9. `TachibanaSpec` 的项目名/エンドポイント是**公开信息推断的默认值**，
   本番発注前に必ず公式 API 仕様書で検証すること（`tachibana-probe` が検証用）。
10. **核心指数仓位 + 实盘**：模拟盘假设「卖指数」与「买个股」都在同一个寄付成交；真实现物账户的买付余力要等卖单成交后才增加，
    买单只能在 9:00 之后下，成交价会偏离开盘价（立花 / RSS 自动下单尚未实现这段先后顺序，目前请用半自动清单手工处理）。
11. 未建模：美股卖出时的 SEC fee（成交额 ×0.0000206，每笔约 0.002%）、NYSE 半日市（每日收盘后运行的流程不受影响）。
12. ~~半自动 `signal` 没跟模拟盘同步~~ → 已解决（2026-09-25）：`signal` / `live` / `daemon` 默认读 `var/sim.json` 的同一档，与 `sim-day` 共用 `_plan_inputs`；幂等记录与流水按券商分文件，只算不发单（dry-run）不拦截、不写流水。
13. **立花适配器（v4r10）还没在真实账户上跑过**：2026-09-25 按公开仕様書（https://www.e-shiten.jp/e_api/mfds_json_api_menu.html）升级 —— 登录只送认证 ID（`sAuthId`），应答里的虚拟 URL 用 RSA-OAEP（SHA-256）私钥解密；下单用 `sOrderSuryou` / `sOrderPrice` / `sGenkinShinyouKubun` 等官方字段并带第二暗証；会话被切断（p_errno=2，03:30 闭局后）自动重新登录一次，发单类不自动重发；交付書面未读时给出明确提示。**2026-06-27 起 API 不再需要电话认证**，可以每天自动登录。测试用本地生成的 RSA 密钥验证解密与字段（`tests/test_tachibana.py`）；真实服务器的行为要开户后在デモ環境用 `tachibana-probe --demo` 确认。
14. **立花只能开一个账户、API 同时只能一个会话**（新登录会让旧的虚拟 URL 失效）：模拟盘把日本分仓和美股指数分仓当两个 ¥100 万账户，实盘在立花是**同一个账户**。实盘前守护进程要改成一个进程、一个会话同时管两个分仓（按票区分持仓、各自记现金账），目前 `daemon` 一次只跑一个分仓。
15. **完全前受制度**：买单下单时现金必须已够；卖指数 ETF 的钱要成交后才能买个股 → 实盘须 9:00 寄付卖出成交后再下个股买单（不再是寄付），模拟盘仍假设两者都按开盘价成交（略乐观）。寄付成行买单按ストップ高价拘束现金，所以系统用寄付指値（收盘 ×1.03）。
16. **换到立花的成本**：按 100 万円规模，個別コース每年约 1.0～1.3 万円手续费，20 年回测年化 8.78% → 8.07%（`broker_cost_study`）；楽天 0 円但只能手动（或 Windows + RSS）。账户越大，手续费占比越低。
